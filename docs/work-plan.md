# Abiapoint — Three-Week Work Plan

## Week 1 — Foundations (completed)

- Define the local business discovery idea and target users.
- Build a responsive home screen and initial interactions.
- Implement search, category/location filters, form validation and saved favourites.
- Document the idea, scope, risks and run instructions.
- Create the public code repository and initial deployment.
- Capture mobile and desktop screenshots, test keyboard access and form errors, and record mentor feedback.

## Week 2 — Components and data (current)

- Refactor repeated card markup into reusable rendering functions.
- Move sample data to `data/businesses.json` and load it asynchronously.
- Add loading, empty, friendly error and retry states.
- Document component boundaries and maintain an issue log.
- Record Week 1 feedback and explain how it was addressed.
- Test search, filters, storage and error handling.

## Week 3 — Quality and delivery

- Improve listing-detail interaction and accessibility.
- Add route handling and a not-found view where feasible.
- Keep favourites available across views and reloads.
- Add automated or repeatable tests where feasible.
- Run an accessibility audit, fix issues and record before/after results.
- Verify mobile/desktop layout and keyboard interaction.
- Deploy the app, update the README and case study, capture screenshots, record a five-minute walkthrough, and complete the reflection/declaration.

## Risks and mitigations

1. **Unverified business information:** clearly label demo data until real business details are confirmed.
2. **Scope creep:** defer accounts, payments, chat and backend work.
3. **Time pressure:** prioritize a complete screen, core interactions, public repository and working deployment before enhancements.
4. **Browser storage limitations:** favourites and user-added demo entries may not sync between devices.
5. **Accessibility gaps:** manually test keyboard navigation, focus states, form errors and responsive layouts.
