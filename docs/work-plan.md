# Abiapoint — Three-Week Work Plan

## Week 1 — Foundations
- Finalize the idea one-pager and this work plan.
- Build one responsive, accessible directory screen.
- Implement search, category/location filters, form validation and saved favourites.
- Create a public code repository, starter README and initial deployment.
- Capture mobile and desktop screenshots; test keyboard access and form errors.
- Present the app to mentors in five minutes and record their feedback.

## Week 2 — Components and data
- Refactor listing cards, search controls and filters into reusable components.
- Select an appropriate mock or verified data source.
- Add loading, empty and friendly error states with retry where data is fetched.
- Add an issue log with bugs, choices and fixes.
- Record Week 1 feedback and how it was addressed.

## Week 3 — Quality and delivery
- Add a listing-detail view and route handling.
- Keep favourites available across views and reloads.
- Add a not-found view.
- Run an accessibility audit, fix issues and record before/after results.
- Write at least three automated tests for a component, interaction and data state.
- Verify deployment, complete README/case study, record a five-minute walkthrough and finish the reflection/declaration.

## Risks and mitigations
1. **Unverified business information:** use clearly labelled demo data until real entries are confirmed.
2. **Scope creep:** defer accounts, payments, chat and backend work.
3. **Time pressure:** prioritize one complete screen, core interactions, public repo and working deployment before enhancements.
